# Headless Virtuoso Daemon, Dirty Index & Single-Session Batch

`oa-git` provides Git-like workspace configuration, local OA source fingerprinting across all three views, single-session batch execution, and a lazy auto-sleep headless Virtuoso daemon—without any HTTP server, database, or edits to `~/.ssh/config`.

## 1. Project Discovery & `.oagit/` Layout

Root discovery runs in strict priority order (`oa_git.project_state.discover_project_root`):

1. Explicit `--root PATH` (inspects only that directory).
2. Walk upward for `.oagit/config.json` (schema `oa-git-config/2`).
3. Compatibility fallback: walk upward for legacy `.oagit.json` (schema `oa-git-config/1`), never deleting or modifying it.
4. Fail closed with `SchemaValidationError` (CLI exit code `2`) suggesting `oagit init`.

Directory layout under `<project_root>/.oagit/` (strict `0700` permissions):

```text
.oagit/
  config.json             # oa-git-config/2 (sorted keys, 2-space indent, no credentials; tracked in Git)
  index.json              # oa-git-index/1 (atomic temp+fsync+replace, flock-guarded; gitignored)
  index.lock              # fcntl.flock(LOCK_SH for reads, LOCK_EX for writes; gitignored)
  ssh/<host-hash>.sock    # Short-lived SSH ControlMaster socket (ControlPersist=max(idle_timeout_s, 60); gitignored)
  daemon/<daemon_id>/     # Per-cds.lib isolated headless daemon state (0700; gitignored)
    daemon.json           # Lifecycle state: starting | ready | stopping | stopped | dead
    heartbeat             # Updated on activity and periodic idle ticks
    daemon_driver.il      # Bootstrap SKILL script passed to virtuoso -restore
    virtuoso.log          # Native Virtuoso log (remote SSH uses per-launch virtuoso-<tag>.log & launch-<tag>.log)
    spool/                # 0700 atomic IPC directory (oagit-spool/1 & oagit-batch/1)
```

The managed `.gitignore` block generated by `oagit init` automatically excludes runtime state under `.oagit/`—specifically `.oagit/index.json`, `.oagit/index.lock`, `.oagit/daemon/`, and `.oagit/ssh/`—while keeping `.oagit/config.json` tracked in Git.

## 2. Dirty Index & Zero-Launch Clean Skip

`.oagit/index.json` is a **local derived cache**, never the electrical or physical source of truth:

- Each entry records fixed candidate OA source files under `oa_libs[<lib>]` (e.g. `<cell>/schematic/sch.oa`, `<cell>/symbol/symbol.oa`, `<cell>/symbol/master.tag`, `<cell>/<layout_view>/layout.oa`).
- Missing candidates are recorded explicitly (`exists: false, size: 0, mtime_ns: null, sha256: null`) so deleted views are never misclassified as clean.
- Fast path: if `(exists, size, mtime_ns)` matches the previous index entry, the cached `sha256` is reused without re-reading the file. If `mtime_ns` changed, `sha256` is stream-recomputed; if content matches and snapshot integrity passes, state remains `clean` with **zero Virtuoso launch**.
- States: `clean`, `dirty`, `missing`, `unknown`. Unmapped `oa_libs` or missing primary OA files when a snapshot already exists are classified as `unknown` (fail-closed, never guessed).
- With `hier=True`, `filter_dirty_targets` skips a root CellView locally only when the root and its entire known transitive `dependencies` subtree are indexed and `clean` (cycle-safe).

## 3. Lazy Auto-Sleep Daemon & Spool IPC (`oagit-spool/1`)

### Session Isolation (`daemon_id`)

Each daemon is isolated by the first 16 lowercase hex chars of SHA-256 over:

```text
realpath(cds_lib) + "\n" + ssh_host_or_empty + "\n" +
virtuoso_cmd + "\n" + remote_workdir + "\n" + sha256(SKILL bundle)
```

Upgrading any SKILL script automatically rotates `daemon_id`.

### Atomic Filesystem Spool Protocol

1. Python writes `<request_id>.req.il.tmp`, `flush()` + `os.fsync()`, and atomically `os.replace()`s to `<request_id>.req.il`.
2. `daemon.il` polls `spool/` every `poll_ms` while active, and falls back to native Cadence SKILL **`ipcSleep(1)`** idle backoff when the spool is empty to avoid busy-waiting CPU overhead. It processes sorted `*.req.il` files, renames each to `<request_id>.processing.il`, calls official `ddUpdateLibList()` to pick up newly created OA libraries, loads the request under `errset`, and dispatches **only allowlisted actions** (`ping`, `stop`, `capture_schematic`, `restore_schematic`, `capture_symbol`, `restore_symbol`, `capture_layout`, `restore_layout`, `capture_batch`, `restore_batch`).
3. `daemon.il` rejects any `output_path` escaping `spool_dir` and never evaluates arbitrary request code.
4. Action scripts write `<request_id>.resp.json.tmp` and rename to `<request_id>.resp.json`; `daemon.il` deletes `<request_id>.processing.il` only after the response exists.
5. Python validates JSON syntax, matching `request_id`, and allowed `protocol` (`oagit-spool/1` or `oagit-batch/1`).
6. Idle auto-sleep: `idle_timeout_s` defaults to **`3600s` (1 hour)**; setting **`idle_timeout_s: 0`** (or `--idle-timeout-s 0`) **disables idle auto-exit** so the daemon remains warm until explicitly stopped via `oagit daemon stop`. When `idle_timeout_s > 0`, after `idle_timeout_s` seconds with no pending requests—or upon `action == "stop"`—`daemon.il` writes `daemon.json` `state="stopping"`, closes open read-only CellViews, and calls `exit(0)`.

### SSH ControlMaster

When `ssh_host` is configured, `SshMuxManager` manages `/usr/bin/ssh` and `/usr/bin/scp` using `-o ControlMaster=auto -o ControlPersist=<max(idle_timeout_s, 60)> -o ControlPath=<root>/.oagit/ssh/<host-hash>.sock` (with `.oagit/ssh/` excluded in the managed `.gitignore` block). It uses configured host aliases from `~/.ssh/config` without ever editing `~/.ssh/config`, cleans up stale control sockets, hardens remote daemon launches against FD hangs and orphaned processes (`-n`, `setsid`, explicit FD closure), and on `daemon.stop()` sends a `stop` request first before running `/usr/bin/ssh -O exit`.

### Single-Shot Crash Fallback

`VirtuosoDaemonClient.execute_with_fallback(...)` lazy-starts the daemon on first request. If startup fails or the daemon crashes/times out mid-request:

1. The client records `last_daemon_error` and marks `daemon.json` `state="dead"`.
2. It falls back **exactly once** to `one_shot_fn()`.
3. It returns `transport="one_shot_fallback"` (never masquerading as daemon success). If `one_shot_fn()` also fails, the original error propagates without further retries.

## 4. Single-Session Batch Capture & Restore (`oagit-batch/1`)

- `batch_capture.il` (`oagitBatchRunCapture`) captures multiple CellViews in one Virtuoso session, dispatching schematic views to `oagitExportBuildResponse` and symbol views to `oagitSymBuildResponse`. With `options->hier`, it traverses non-PDK/non-skipped custom instances up to `max_depth` (default `32`, emitting `hierarchy_depth_exceeded` if exceeded), detects cycles in `cycles` without infinite recursion, optionally captures matching custom `symbol` views, and closes every CellView opened by the script.
- `batch_restore.il` (`oagitBatchRunRestore`) executes per-target atomic draft-and-publish restore in one Virtuoso session and, when `options->readback` is true, immediately captures the published target in the **same session** (returning inline `readback`) to eliminate a second Virtuoso cold start.
